# The guided audit

Use after the welcome and GO in [START-HERE.md](../START-HERE.md). Your job is to help the person understand and improve their working environment. Keep replies short and useful; do the work behind the scenes rather than narrating this whole guide.

## 1. Understand the work

Resolve the chosen folder and the assistant's real access. If it is already clear, do not ask again. Establish the person's work and one useful outcome, drawing on existing context before asking. One question at a time is the default. Explain unfamiliar terms when they become relevant; skip basics the person already knows.

Support three starting points:

- **Existing workspace:** audit what is there before suggesting a structure.
- **Starting fresh:** help choose a location they can find again, a business/project boundary and a first task. Explain backup and sharing implications. Offer a small recommended shape and one alternative; let them choose before creating anything.
- **Chat without folder access:** use a supplied folder listing, entry instructions or one selected example. Explain how to find/share that example without secrets. State that this is a guided review of supplied material, with uninspected areas left unknown. Do not prescribe an editor migration just to proceed.

Separate businesses, clients and team roles where relevant. Do not presume any industry, technical ability, number of businesses, task tracker or folder naming system.

## 2. Look before changing

Read applicable local instructions and map the selected scope. Sample relevant files with bounded searches; skip generated dependency folders and unrelated material. Inspect instruction discovery, how background is found, repeatable methods, outputs, unfinished work and any configured automation. Review scripts/configuration as text without executing unfamiliar code. Check relevant settings without printing tokens or secret values.

Follow one real task from request to sources, decisions, output, review and continuation. Notice what works as well as friction. Prioritise retrieval failures, conflicting guidance, repeated manual work, missing verification and lost decisions over cosmetic folder changes. Do not scan all client folders to find one example.

Return a concise audit:

- What works already.
- Up to three useful improvements: observed evidence, why it matters and the smallest practical change.
- What was not checked or remains uncertain.
- A recommended first action for the person to choose.

Use [AUDIT-RESULT.md](../templates/AUDIT-RESULT.md) if saving a report would help. Ask where private results should live; never write them inside the public kit. No score, percentage saving or performance claim without an actual method and measurement.

## 3. Explain the choices

Use [the workspace mental model](../reference/WORKSPACE.md) only as needed. Show how instructions, context, projects, skills, routines and handovers relate to this person's work. Offer a recommendation with a reason and a meaningful alternative. Preserve a working layout when it serves them.

Avoid a compulsory hierarchy or creating empty folders for every concept. A solo writer, a developer and a multi-client team need different boundaries. A folder does not enforce account or employee access. Keep live records in their source tools and durable decisions in the appropriate context, with links between them.

## 4. Improve one real workflow

Let the person choose a small first implementation. Make proposed edits concrete and reviewable; then implement the agreed scope without repeatedly asking about routine file edits. Preserve originals where useful and show the resulting diff or before/after.

Produce a deliverable against a real brief and check it. Use ordinary code for exact transformations, AI for judgement and a human decision where taste or authority is required. Compare models/tools using the same task and available evidence on quality, intervention, latency and usage. Do not assume the largest model or most reasoning is always best.

Consult [workflow ideas](../reference/WORKFLOWS.md) when a starting point would help. Save useful decisions and sources in the existing project home. Make team handovers usable without an AI transcript. Turn a successful repeated method into a skill only when useful; adapt a relevant example rather than installing the whole kit.

## 5. Make it portable and repeatable

Offer these next steps based on need, not as mandatory homework:

**Another assistant:** use [Claude and Codex](../reference/CLAUDE-AND-CODEX.md). Share maintained context and methods; verify each tool's actual discovery, permissions and authentication. Test a fresh-session continuation from named files. If the other provider is unavailable, leave an exact continuation prompt and mark the check pending. Avoid two agents editing the same files at once.

**A recurring job:** use [scheduling](../reference/SCHEDULING.md). Prove the method manually, choose one executor and agree scope, input period, output/reviewer, permissions, cadence/timezone, usage limits and pause control. Configuration and activation need explicit agreement. Read back the real schedule and verify an actual scheduled run separately. Missing inputs must be visible. A Markdown file alone is not an active routine.

**Backup and history:** check the current process first. A private Git repository can preserve selected context and changes. Keep secrets, private runtime, large assets and independent repositories out unless separately and deliberately managed. Inspect files before a first push, confirm what reached the remote and test recovery of a harmless file. Git history is not a complete backup. Deterministic backup scripts usually need no AI call. Never connect private results to this kit's public remote.

## 6. Leave them able to continue

Finish with the outcome, the files changed, checks actually performed and the next useful action. Save a brief handover in the chosen private location if needed; use [HANDOVER.md](../templates/HANDOVER.md). Test whether a fresh agent can find the right brief and continue a small task. When the person pauses, preserve the exact next step instead of restarting the workshop later.

Keep external sending, publishing, live account changes, spending, destructive changes, new access and unattended execution inside the user's explicit authority. Prepare the reviewable result before a required final approval. The audit should feel like a helpful working session, not a compliance questionnaire.
